# AGENTS.md — Kanea

Guidance for AI agents (and humans) working in this repository. Read this before writing any code.

## What this is

**Kanea** is a lightweight, single-binary container orchestration platform written in Go — "container orchestration in one binary." It runs services on **containerd**, networks them with **its own eBPF datapath** (nothing from the Kubernetes stack underneath — and since PRD v1.36 no Cilium either), terminates TLS with **Let's Encrypt**, and ships a **React + shadcn/ui** dashboard, an **MCP server** for AI agents, GitOps pipelines (kaniko), eBPF-driven autoscaling, and S3-backed state replication.

**[`PRD.md`](./PRD.md) is the north star.** It is complete and internally consistent (v1.40). Every architectural decision, naming rule, milestone, and risk is specified there. When this file and the PRD disagree, the PRD wins — and the disagreement means one of them needs an amendment.

Things a future change is most likely to trip over:

- **Metrics never touch the Store** (constraint #2). `internal/scaling` is an in-memory ring, ~27 MiB at the 2 000-alloc target, measured by `TestFootprintAtTargetScale`.
- **"No data" is never zero** — in the time series, the evaluator, the exporter and the dashboard alike. A missing metric and an idle service lead to opposite decisions, and each layer has a test saying so.
- **The autoscaler is not a second scheduler.** It writes one number; the reconciler converges. `kanea scale` uses the same route.
- **The scale-decision budget is 20 s** from a sustained breach (PRD v1.21), not the 15 s v1.1 promised — see the amendment for why 15 s costs more than it buys.
- **Accounts live in the Store, not the config file** (PRD v1.18), and `--oidc-client-secret` / `--acme-dns-tsig-secret` are `secret:` references, never literals.
- **A repository speaks for its own project and no other** (PRD v1.23). `gitops.parseCheckout` refuses a synced spec that declares another project — it is the same boundary R5 draws for secrets, and it is the only thing between "can push to one repo" and "owns every service on the node".
- **The git webhook route is the one non-§13 authentication** (`docs/THREAT_MODEL.md` §3.8): a per-project HMAC over the raw body, replay-rejected, audited. It never deploys from the request — it marks the project and the sync loop re-reads the source over Kanea's own credential.
- **Builds are serialised and refused when full, never blocked** — §10.2 makes isolation collective, so a second concurrent build shares the first's budget. `queued` is a real state, and shutdown cancels what is still waiting.
- **`notify.Publish` never blocks and never returns an error**, by design (constraint #8). An error return would invite `if err != nil { return err }` in a reconcile loop, turning an undeliverable Slack message into a failed deploy. Drops are counted; the queue-full warning fires once, so a notification storm cannot become a logging storm.
- **The event vocabulary lives in one place** (`internal/notify`), and `jobspec` validates filters against it. That is why the dependency points jobspec → notify and the route *builder* lives in `cmd/kanea` — two implementations of "is this a known event" drift, and they drift into a spec that passes `kanea plan` and matches nothing at runtime.
- **Notification egress is checked at dial time, on every resolved address**, and redirects are refused (§14 A10, `docs/THREAT_MODEL.md`). A hostname is not a destination.
- **go-git ≥ 5.19.1 and go-billy ≥ 5.9.0 are security floors**, not preferences (GO-2026-5693, GO-2026-5597). The billy one is a path traversal in the chroot filesystem `Materialize` clones a working tree through — repository-controlled paths written to disk. A downgrade fails `make security`, which is how it should be found.
- **A service with a `build` block and no `task.image` is legitimate** (§6.2 R8) and the reconciler skips it until the first build pins a digest. `${GIT_SHA_SHORT}` and its siblings survive parsing as literal references — their value only exists once a commit is checked out.
- **A deploy is a spec-hash mismatch** (PRD v1.25). `reconciler.SpecHash` covers only what is baked into a container at creation; adding a field to `Desired` does *not* change it unless you add it to the hash's own struct, and whether a new field should roll allocs is a decision to make there. A record with an empty hash is adopted, never rolled — that is what stops an upgrade of `kanead` from replacing every alloc on the node.
- **`max_parallel` bounds allocs that are down, not replacements in flight.** Anything already unavailable spends the budget first, so a deploy that starts going wrong stops instead of walking through every replica. `min_healthy` applies only to allocs the current deploy has already replaced.
- **`AllocRecord.Healthy` is only ever written by a probe.** A service with no `check` block has it false for every alloc, forever. Read it through `Probed()` or behind `Check.configured()`; testing the field alone reports every check-free service as broken.
- **A restart is a spec change, not a second path to the runtime** (PRD v1.26). `POST /v1/services/{p}/{s}/restart` bumps `Desired.Generation`, which is in the spec hash. The generation belongs to the running service, so `handleApply` carries it over — an apply that reset it would restart the service a second time.
- **MCP tools reach the platform only by HTTP against the API's own handler** (§16.3). That is what makes "no side channels" structural: a tool's only verb is "send this request", so it cannot be more privileged than the credential its caller presented. Nothing in `internal/mcp` may take a `Store`, a secrets store, or an auth store.
- **There are no secret tools, at any tier** (PRD v1.26). §16.3's safety rule is that no tool returns a secret value; the implementation goes further and gives an agent no secrets verb at all. `TestNoToolReadsASecret` fails if one appears.
- **An MCP refusal is a tool result, not a JSON-RPC error.** A protocol error is handled by the client library and never reaches the model; a `isError` result does. An *unknown tool* is the reverse — that is a client bug.
- **An archive's last chunk is sealed under different additional data** (PRD v1.27). That is the only thing standing between a truncated snapshot and a restore that decrypts cleanly to half a platform. A final chunk is always written, possibly empty, so "a short read is the last chunk" stays true when the plaintext is an exact multiple of the chunk size.
- **The change log is pruned only after the upload returns**, segments only below the *oldest kept* archive, and a replay that meets an unreadable segment stops rather than skipping it. Skipping one resurrects whatever a delete in it removed, and the reconciler starts it.
- **The replication cursor is derived from the sink**, never stored. In the Store, writing it emits a change that needs shipping, which writes it again.
- **The Store does not migrate itself at Open** (§15.4). A migration rewrites state in place, and the copy that makes a bad one survivable needs the database open and the migration not started — exactly one window, between `Open` and `Migrate`. Each step's data change and version bump share a transaction.
- **A restore is staged, never performed in place.** `internal/api`'s `Backups` interface has no method that restores; the daemon does it at the next start, before anything opens the Store. That is the interface, not a check.
- **`buildReplication` returns `api.Backups`, not `*backupService`.** A nil concrete pointer in an interface field is a non-nil interface: every "is a destination configured" test would answer yes and then panic.
- **A Sink's `Put` does not own the reader it is given.** `net/http` uses an `io.ReadCloser` request body directly and the transport closes it, so passing an `*os.File` hands the caller's handle to net/http. That defect uploaded every S3 snapshot successfully and then failed before writing the manifest — an invisible archive, every time — and no fake server could catch it, because every unit test passed a `strings.Reader`. The `s3-interop` CI job against MinIO is what found it.
- **Cancelling a context a websocket read is blocked on closes the connection.** That is coder/websocket's documented behaviour — a half-read frame leaves the stream unusable — so an exec read loop scoped to the exec itself tears the socket down the moment the process exits, and the exit frame is written to a dead connection. The loop is scoped to the handler for that reason. It presented as an exit code that was always zero, which every test but one silently accepted.
- **Kanea installs its own runtime, and the manifest is the version matrix** (PRD v1.30, §5.2.12). `internal/provision/components.json` pins containerd, runc and buildkit by version and SHA-256 (images by digest), it is compiled in via `go:embed`, and it is *also* the §15.4 matrix `kanea doctor` enforces — there is deliberately no second copy. **Hashes are never fetched**, so bumping a component is a code change with a review, and the `manifest-verify` CI job catches an upstream re-tagging a release. (The network layer is not in the manifest — the datapath's programs are compiled into the binary, PRD v1.36 §5.2.5.)
- **The install bootstraps in one direction, and manifest order is install order.** containerd + runc first, then containerd *starts*, and only then is the buildkit image pulled through it. `Manifest.Select` reorders whatever it is asked for into manifest order for exactly this reason — `--only buildkit,containerd` must not mean what it says.
- **BuildKit's binaries are extracted to the host from its image.** `buildkitd`/`buildctl`/`rootlesskit` are self-contained and extract cleanly; there is no longer an image component that *runs* as a task (cilium was the one, removed in v1.36), so `kanea supervise` is gone with it.
- **Files come out of images by walking layers newest-first, not by mounting a snapshot.** No mount syscall, no snapshotter dependency — and the same code serves an OCI archive out of an offline bundle, which is what makes image components work air-gapped at all. Whiteouts are honoured; the early exit is what keeps a large image from being read in full.
- **`install.go` never speaks HTTP.** It asks a `Source` for bytes and verifies them against the embedded hash. `fetch.go` is that over HTTPS, `bundle.go` over a local directory — one install implementation, so the air-gapped path cannot rot. The `install-smoke-airgapped` CI job runs it inside `unshare -rn`, where a stray network call fails instead of quietly succeeding.
- **A bundle is not trusted more than the network.** Its contents are verified against the hashes in the *installing node's* binary, never against the metadata inside it. A bundle that supplied its own hashes would be a bundle that authenticates itself.
- **Nothing at a distribution's paths is touched.** Kanea's containerd lives at `/run/kanea/containerd.sock` under `/usr/local/lib/kanea`, with its own CNI bin dir and conflist — `/opt/cni/bin` and `/etc/cni/net.d` are shared with whatever else on the node uses CNI. `--containerd external` adopts an existing daemon, and it is the one case §5.2.11's drop-in language still describes: **you do not need a drop-in for a unit you wrote.**
- **The systemd units carry constraint #11**, not the Go code. `MemoryMin` and `OOMScoreAdjust` are systemd's to set, and `kanea-edge` must never gain an `After=kanead.service` — north-south traffic surviving a control-plane restart is why it is a separate process at all. The units use `Type=exec`: nothing sends `sd_notify`.
- **A passthrough spec names a grant, never a path** (PRD v1.31, §6.2 R17–R18). `device` and `socket` blocks have no field for a device node or a socket path — not a validated one, *none* — because a spec is not a trusted document: GitOps deploys them automatically, so anything a spec can declare, anyone who can push to a synced repo can declare. The node holds the mapping in `--passthrough-config`, grants name the projects that may claim them, and the default is that the file does not exist. `internal/passthrough` is that policy and is the sibling of `storage.HostPathPolicy`, **not a relaxation of it** — R15's "must be a directory" check is load-bearing for host volumes and stays. Resolution is per alloc, after symlink evaluation, with a type check, and a failure fails the alloc: a transcoder silently running without its GPU looks healthy and does the wrong thing.
- **A granted runtime socket is root on the node, and the docs say so.** There is no containment and none is claimed; `nosuid,noexec,nodev` restrict the filesystem entry, not the protocol. A filtering proxy would be a real mitigation and is deliberately not built — it is a second protocol to keep current with containerd, and being subtly wrong about it is worse than a control nobody can misread. §14 A05's "no `privileged` escape hatch" now reads "none a job spec can declare", which is the claim that was actually true all along.
- **A device needs an allow rule, not just a node.** containerd's default spec carries `{Allow: false, Access: "rwm"}` and `withResources` *preserves* it, so `oci.WithLinuxDevice` must be appended after — a `Linux.Devices` entry alone is a device the container can see and cannot open. `spec_test.go`'s `buildSpec` seeds that deny-all for exactly this reason: without it a device test asserts on an allow rule with nothing to override and passes on a spec containerd would not run.

- **Auto-update is not a second deployer** (PRD v1.32, §6.2 R19). `internal/autoupdate` resolves a tag, writes one field, and the reconciler converges — the same relationship the autoscaler has with the scheduler, and the same `Deployer`-shaped seam §10.2's pipeline uses. Nothing in it touches containerd. That is what makes an automatic update roll with `max_parallel`, wait `min_healthy` and honour the health check: it *is* an ordinary deploy that nobody typed.
- **The declared tag and the running digest are separate fields.** `Desired.Image` keeps the tag because the next poll re-resolves it; `Desired.PinnedImage` is what `RunImage()` returns and what `AllocSpecFor` creates from. Pinning over `Image` would destroy the input the feature reads. Only `PinnedImage` is in the SpecHash `material` — `RollbackImage`, `ImageCheckedAt` and `ImageUpdatedAt` are bookkeeping, and hashing them would roll every auto-updating service on every poll.
- **`handleApply` carries the pin over, like the generation** — and drops it in exactly two cases: the operator edited `image` (the spec is naming a different tag, so a carried pin would run the old one and silently ignore the edit) or turned `auto` off (the spec gets authority back). Without the carry-over, every `kanea apply` would unpin, redeploy onto the bare tag, and re-pin on the next poll: two deploys of a service nobody changed.
- **Convergence means healthy only where a check exists.** `AllocRecord.Healthy` is written solely by a probe, so requiring it unconditionally would call every check-free service permanently failed and revert every update it ever made. Without a check the standard is "running at the new spec hash and not crash-looping", which is the strongest true statement available.
- **`EnsureImage` cannot detect a moved tag** — it returns the local digest whenever the image is present, which is by construction the one already running. That is why `ResolveRemote` exists and fetches only a manifest. Registry credentials reach the runtime as bytes the *caller* resolved: `internal/runtime` never resolves a `secret:` reference, so the reconciler and the watcher each resolve their own.

- **The certificate bundle is a merge, and each source replaces only its own contribution** (PRD v1.33, §7.3). `Publisher.SetCertificates(mode, certs)` is per source, never wholesale: three sources publish into one file on their own schedules, and any one of them writing the whole set would drop the other two. The publisher bumps the bundle index **only when the material actually changed** — the edge reloads on a byte difference, so an unchanged set with a fresh index is a keyring rebuild every poll once a file-backed source is stat-ed every minute. And nothing ever falls back to a weaker source: a `provided` certificate that cannot be resolved serves plaintext rather than silently becoming self-signed, because a browser interstitial is something an operator learns to click through.
- **`Expose.TLSMode` is resolved on the node, not in the CLI.** `toDesired` runs client-side (`kanea run`, MCP, the pipeline), so baking `--tls-default` in at conversion would make one spec mean different things on two machines. An empty mode on a stored record means "the node decides", which is why the pre-v1 `LetsEncrypt` bool survives on `Desired` as a read-only field — it is what makes an old record still mean `acme` without a schema migration.
- **A published port is a listener the edge binds, and `routesArePublished` is where it goes wrong.** That check compared only `[]edge.Route`, so listeners added to the snapshot but not to the comparison publish exactly once and never again — a steady-state pass finds the routes equal and returns early. It is `snapshotIsPublished(routes, listeners)` for that reason. `Publish` is deliberately **not** in the `SpecHash` material, like `Expose`: nothing about a node port is baked into a container, and hashing it would roll every alloc to fix a CIDR typo.
- **Which node ports a spec may claim is enforced at `handleApply`, not at plan.** `kanea plan` pre-checks the same policy over `GET /v1/edge/policy` so the refusal lands in front of whoever typed the port — but that is a courtesy. GitOps reaches the Store without ever passing through the CLI, so a check that lived only in the CLI is a check a `git push` walks past. The zero `PortPolicy` is publishing *off*, not publishing open: a server built without one refuses.
- **The container subnet is a set of flags on `kanead`, because `kanead` is the IPAM** (PRD v1.36). `--node-cidr`/`--cluster-cidr` are install-time, rendered into the `kanead` unit's argv, and validated before startup — `parseAgentCIDRs` gates the daemon (GitOps and systemd reach it without `doctor`), while `cmd/kanea/preflight.go`'s `checkSubnets` is the courtesy pre-check. Both enforce the same rule: IPv4 prefixes, node inside cluster, and **neither overlaps `--service-cidr`** — a service VIP handed an address that is also a container address is the failure the overlap check exists to catch.
- **`--tls-certs-config` reloads on every pass; `--passthrough-config` loads once.** The divergence is deliberate: a device grant is a decision, and a certificate is a thing with an expiry date that a renewal tool rewrites behind Kanea's back. `Changed()` hashes the config *and every file it names* rather than stat-ing them — certbot writes-then-renames, so the mtime it leaves is whatever the temporary file had. That is also why it is a poll and not fsnotify: the rename replaces the inode a watch is registered on.
- **A `tcp` listener refuses what it cannot enforce.** `rate_limit` and `headers` on one are a plan error *and* an invalid snapshot, checked twice like duplicate domains. A control the edge silently drops is worse than one the spec never claimed. Half-close is mandatory in the relay (`io.Copy` returns, then `CloseWrite`) — Postgres and most line protocols need EOF while still writing back — and `ip_restriction` is checked before the upstream is dialled, because the upstream sees the edge's address and cannot do this itself.

- **A nil user and a nil volume owner are not zero, and `omitempty` is what keeps them apart** (PRD v1.34, §6.2 R23–R24). `Desired.User` and `Volume.UID/GID/Mode` are pointers with `omitempty` json tags for one reason: they are in the `SpecHash` material, so a field that serialised as `0` instead of vanishing would change the hash of every service on the node and **upgrading `kanead` would roll every container on it**. `TestSpecHashIsUnchangedForASpecWithNoUserOrOwnership` pins the pre-R23 digest against that. The same distinction is load-bearing at runtime: nil means the image's own `USER` stands, and reading it as `0:0` would silently promote every workload to root. The two halves of an owner are independent too — an undeclared gid is chown(2)'s `-1`, not group 0.
- **The ownership refusal list is duplicated, on purpose, and it is not a policy.** `jobspec.ownershipRefusedBy` refuses `host` and `nfs` at `plan`, which is where an operator should meet it; `storage.ownershipRefusedBy` refuses them again at mount time, for a record that reached the Store another way. A dependency from `storage` to `jobspec` would point the wrong way, and the map is two entries. Unlike R15's allowlist and R17's grants there is **no node-side half** of R23/R24 — a uid is a number, not a resource the node has to permit — so `--passthrough-config` has no analogue here and adding one would be inventing a decision nobody makes.
- **`oci.WithUser` and `oci.WithUserID` are not used, and must not be.** Both read `/etc/passwd` out of the container's rootfs to fill in the group, which is a container-controlled file deciding what the control plane runs a process as. `withHardening` sets `Process.User` directly, and it works only because `specOpts` is appended *after* `oci.WithImageConfig` — a reordering silently gives the image's `USER` back. Nothing extra is needed for exec: both `Exec` and the interactive path copy `*spec.Process`, so a health probe and `kanea exec` inherit the user for free.
- **A local volume is chowned; a mounted one is not.** For `smb`/`s3` the directory `ensureVolumes` creates is only the mount point and vanishes under the mount, so ownership travels in the mount command instead — `uid=`/`gid=`/`dir_mode=`/`file_mode=` for cifs, `uid=`/`gid=`/**inverted** `umask=` for s3fs, and `--uid`/`--gid`/`--dir-mode`/`--file-mode` for mountpoint-s3, which takes flags rather than `-o` and is why `Resource.Options` is dropped on that branch. Note `storage.Resource.Mode` is the ro/rw driver selection and has nothing to do with a file mode; ownership lives on `Request`, not `Resource`, because it is the volume's decision and two services mounting one resource get distinct targets.
- **Volume ownership inheritance is resolved in `jobspec`, not on the node, and it stops at a driver that cannot carry it.** Unlike `Expose.TLSMode` it is not node-dependent, so resolving it at parse time is what lets `kanea plan` show what will actually be applied. `resolveVolumeOwnership` is a *spec*-level pass rather than part of `convertService` for one reason: it has to look up the storage a volume names, and a service does not have the storage list. Skipping `host` and `nfs` there is what keeps R24 additive — if inheritance applied and then failed validation, adding a `user` block would break every NFS volume the service happened to have and there would be no field to opt out of a default nobody typed. Only a *declared* uid/gid/mode on those drivers is an error.

- **The edge publishes two metric families and they must never merge** (PRD v1.35, §9.1.1). The **aggregate** one — `kanea_edge_requests_total{service}` and its histogram — is the autoscaler's input and is differenced into `internal/scaling`'s rings. The **labelled** one — `kanea_edge_service_*{service,code,method,protocol}` — is retained verbatim by `EdgeScraper` and republished unchanged by `/v1/metrics`; it **never enters the time series**. Constraint #2's cap and `TestFootprintAtTargetScale` are why, and so is the evaluator: a rule names one `rps`, not forty. They carry *different metric names* rather than one name at two cardinalities, because one name would double-count under any `sum()` and fail `promtool check metrics`. `TestTheLabelledFamiliesNeverReachTheTimeSeries` is the regression that guards it.
- **Every label dimension on the edge is chosen by someone else, so each is bounded by construction.** `method` is a request-line token an attacker picks — allowlisted to nine, everything else `OTHER`. `protocol` is derived from the connection, never read from `r.Proto`. Past `maxSeriesPerService` a service folds into one overflow series and bumps `kanea_edge_series_dropped_total` — and the cap counts the overflow's own slot, so the map never holds one more than the number says. A cap nobody can see is indistinguishable from a leak, which is why the drop counter is not optional.
- **`kanea_edge_server_up` is emitted only for allocs a probe has run against.** `AllocRecord.Healthy` is written solely by a probe, so gating on `Probed()` is what stops every check-free service reading as entirely down. Same rule as §9.2's "no data is never zero", applied to health. `kanea_edge_up` exists for the same reason one level up: `kanead` does not supervise the edge (§5.2.6) and keeps serving `/v1/metrics` without it, so a gap needs a cause.
- **A certificate expiry gauge is per certificate, not per name.** A wildcard covering forty subdomains is one thing that expires on one date; forty gauges would make a single renewal look like a fleet-wide event. `edge.Certificate.Source` is `omitempty` and an empty one renders as `unknown` — a bundle from a pre-v1.35 `kanead` still gets its expiry published, because the number is worth more than the label.
- **Exposition label values are escaped explicitly, not with `%q`.** Go quoting renders non-ASCII as `\xNN`/`\uNNNN` and Prometheus unescapes neither, so a certificate whose common name is not ASCII would come back as literal backslash text. The format defines exactly three escapes and `escapeLabelValue` emits exactly those.

- **The datapath is Kanea's own, and IP is identity** (PRD v1.36, §5.2.5). `internal/datapath` is three eBPF programs, pinned maps under `/sys/fs/bpf/kanea`, netlink plumbing and one nftables rule — no cilium, no etcd, no CNI, no network agent. `kanead` allocates every address, so the identity map is written by the allocator itself: no identity protocol, no label race, no settle window. The numeric project/service ids behind the maps are Store-allocated and **never reused** — reuse would make a pinned map lie after a restart.
- **Attach is deny-closed by construction, and the order is load-bearing in a new way.** Identity map write → veth created with the host side *down* (`kn` name prefix + `kanea/<alloc>/<ip>` ifalias — the ownership mark that makes the reaper safe where `NetnsNetwork`'s bare namespaces are not) → tc policy attached → addresses and static neighbors → link up → the host `/32` route **last**. A skipped step fails closed because an identity miss is a drop. There is no wait loop, no readiness poll and nothing to retry.
- **LB is connect-time socket rewrite at the root cgroup**, held by a pinned `bpf_link`. **Established connections never consult a map** — `kanead` can restart, or recreate every map, without touching a live flow — and backend sets change by **generation flip**: the new set is written under gen+1, one atomic update of the service entry commits it, the old generation is deleted. Half-updating `svc_backends` without flipping `svc_v4` is the torn-set bug the pattern exists to prevent. A VIP with no backends refuses at `connect()` (EPERM), never a black-hole timeout. **Service ports are TCP-only**, refused at `plan` otherwise.
- **Policy is SYN-gated and stateless, and the threat model says so.** Non-SYN TCP passes — that is what lets cross-project `allow_from` replies flow without a conntrack — so an in-node ACK probe passes the filter and is stopped only by the stack's RST. Deliberately weaker than conntrack; the upgrade (an LRU conntrack map) is additive, not a rewrite. The egress program drops `169.254.0.0/16` (§14 A10, now actually enforced) and any service-CIDR destination that escaped connect-time rewrite.
- **Datapath state is derived and survives restarts.** Programs, maps and the cgroup link are pinned with a schema stamp; a mismatch recreates and repopulates them inside the first reconcile pass — safe *because* established flows bypass the maps. IPAM is rebuilt from the marked veths at startup and never stored: a leaked reservation cannot outlive the interface that holds it. Nothing under the pin root is ever backed up.
- **The generated BPF artifacts are committed**, produced under a digest-pinned toolchain (`make bpf`) and verified by the `bpf-verify` CI job — `go build` needs no clang, and the target node needs no BTF (no CO-RE, no `vmlinux.h`; the programs read only UAPI context types). Editing a generated file by hand is a CI failure, not a code path.
- **East-west metrics come from the datapath's own per-CPU counters, on by default**, keeping the names `flows_per_second`/`drops_per_second` so no scaling spec changes meaning. Hubble is gone — it shipped unreachable (no generated unit ever enabled it) and nothing consumed it.
- **`--network netns` remains the dev/CI mode** (bare namespaces, no policy, no LB, explicitly unsupported for deployment); `ebpf` is the default. Masquerade is one rule in the owned `kanea` nftables table — kernel conntrack does the NAT — and a foreign FORWARD-drop policy (docker, ufw) is a `kanea doctor` finding, not something the datapath silently fights.

- **Protective state survives a restart at its transitions, never at its sampling rate** (PRD v1.37). Four things are durable in the `kv` bucket: the circuit breaker's trip (`kv:reconciler/breaker`, written on trip and reset only — the failure window is rebuilt live), the autoscaler's per-service cooldown (`kv:scaling/cooldown/<project>/<service>`, written **inside the scale action's own Apply batch**, so it costs zero extra replication), account login lockouts (`kv:auth/lockout/<account>`, written on the locking transition, deleted on the next good login), and — with no new state at all — a startup sweep that closes pipeline runs a crash stranded at `queued`/`running`. Persisting any of these per sample would be a metric stream through the Store, which constraint #2 forbids.
- **The evaluator refuses to shrink a service until it has *observed* a full stabilization window.** An empty history satisfies "nothing was higher in the window" vacuously, so without the guard the first post-restart evaluation could scale down through a window nobody watched. The seeded cooldown carries the pre-restart timestamp; `serviceState.since` is always stamped from the evaluator's own clock.
- **Only account lockouts are persisted — per-source lockouts are memory-only, and unknown names never reach the Store.** Both key spaces are attacker-chosen (source addresses; the `name` field of a failed login), and a persisted entry per attempt would convert brute force into CDC/S3 write amplification. Account names are bounded because `checkName` validated them at creation. The webhook replay cache resets on restart for the same reason, and a replayed delivery re-syncs a commit `LastCommit` already records — idempotent.
- **Replication's last-segment/last-snapshot times are derived from the sink at startup, like the cursor** (`Archiver.Resume`). A stored timestamp would emit a change that needs shipping, which updates the timestamp. `Segment.Modified` is the sink's upload time — possibly from a previous process, which is the point: `Status` answers "when did replication last succeed", not "since this process started".
- **A crash-orphaned `queued` run is cancelled, never re-enqueued.** Its request was derived from the project config at queue time, and re-deriving it at startup could build something other than what was queued. `running` runs are failed with an honest message; swept runs become terminal, so `Prune` retention finally applies to them.
- **Mount backoff deliberately resets on restart** (recorded in v1.37, not an oversight): the kernel mount table is the ground truth `Ensure` consults first, and the post-restart cost is one honest mount attempt per target before the schedule re-arms.

- **The stats history endpoint serves gaps as absent points, never zeros** (PRD v1.38). `GET /v1/stats/history` is the in-memory TS's `Range` over the API — sparse `{at, value}` pairs; an unwritten ring slot is simply not serialised. The two node series it needs (`node_cpu_percent`, `node_memory_percent`) enter the TS under names the exporter's fixed list never publishes, so `/v1/metrics` is unchanged; node `rps` is summed at read time and node `p95` is an rps-weighted approximation, labelled as such.
- **The spec editor renders and applies through one path** (PRD v1.38). `POST /v1/spec/render` and `POST /v1/spec/apply` share one `SpecRenderer` (implemented in `cmd/kanea` beside `toDesired`, the `gitops.Applier` seam shape), and apply calls the same core `PUT /v1/services` uses — generation carry-over, pin carry-over and the port-policy check are inherited, never replicated. A render scoped to a project refuses a spec declaring any other (the §10 boundary). `GET /v1/spec/source` generates HCL from desired state, is marked generated, and is gated by a round-trip test — a field that cannot round-trip refuses generation by name rather than emit a lie.

- **Request auth lives on the restricted side of the §5.2.6 boundary** (PRD v1.40, §6.2 R27). The route table is world-readable, so `routes.json` carries only a fail-closed `auth` marker; the verifier material rides the certificate bundle (0640) the edge already polls. What crosses is less than what was declared: bcrypt lines pass through, bearer tokens become SHA-256 hashes, and only a JWT HS256 key is a secret (RS256/ES256 carry a public key). A marked route with no material is **503, never open** — a missing certificate's rule, applied to auth. The JWT algorithm is **configured, never read from the token** (alg-confusion is refused on mismatch; `alg:none` cannot exist), and there is **no JWKS fetch** — the edge makes no outbound calls. `internal/edge/authz.go` verifies; `internal/reconciler/authz.go` projects (resolving `secret:` refs, hashing tokens); the spec side is `internal/jobspec/authz.go`. Auth runs **after the rate limit** in the proxy chain, with a success-only bcrypt cache that is not an oracle.
- **The invoker signs with the webhook channel's `Sign`, and a resolve failure drops rather than sends unsigned** (PRD v1.40, R26). A function's `signing_ref` is resolved per delivery by `internal/functions`; the signature is `notify.Sign` over the exact body with `X-Kanea-Timestamp`/`X-Kanea-Signature`. A reference that stops resolving fails the invocation (`function.invoke_failed`) — an unsigned POST to a verifying function is a dropped control (R16), not a delivery.

- **A function is a service that was lowered, and `Function != nil` is the only marker** (PRD v1.39, §6.2 R25–R26). The `function` block lowers at parse time to a `Service`/`Desired` with `Runtime: "wasm"`; there is no `task.runtime` field and must not be — R25's refusals (volumes, devices, sockets, capabilities, `user`, exec probes, `scaling`) are about one block, and a second way to reach the wasm runtime would be a way around them. `GET /v1/functions` filters on `Function != nil`; the Services list filters it out; `toHCL` regenerates a `function` block from it. Both `Desired.Runtime` and `Desired.Function` are `omitempty` **in the SpecHash material too** — one missing `omitempty` rolls every service on the node at upgrade (the R23 lesson, pinned by test). Trigger config is deliberately NOT in the SpecHash: nothing about a cron schedule is baked into a container, and hashing it would roll an alloc to change an invocation time.
- **The event/cron invoker dials VIPs the Store derived, and is deliberately not behind `notify.EgressPolicy`.** The egress guard exists because a channel URL is attacker-influencable text; the invoker's target cannot be influenced — R26 gives the spec no URL field — so consulting the guard would be theatre and *weakening* it for private ranges would be a hole. Redirects refused, responses drained under a size cap, short timeouts, non-blocking enqueue with a visible drop counter (constraint #8's `Publish` discipline). R26 refuses `function.*` patterns at parse AND the invoker skips them at match time — the R23-style duplicated check, because a feedback loop with no damping is what it prevents.
- **Function invocation metrics are datapath connects, not edge rps.** A connect to the function's VIP is an invocation whether it arrived through the edge, east-west, or from an invoker — edge rps silently misses the east-west calls. `flows_per_second` for the lowered service is the one number (§9.1); under `--network netns` the fallback (edge rps + invoker counters) is labelled partial. `idle` requires the counter observed present and zero — absent data renders `active`, never `idle`.
- **The containerd unit now sets `Environment=PATH=`** because containerd resolves `io.containerd.wasmtime.v1` to a binary named `containerd-shim-wasmtime-v1` on **its own** PATH, and Kanea's bin dir was never on systemd's default. Removing that line breaks every non-runc runtime silently at task-create. For `--containerd external`, a missing shim is a `kanea doctor` finding — never a drop-in on a unit Kanea did not write.

**Deliberately not built** — decisions, not gaps, so they are not "fixed" by someone who mistakes them for oversights:

- **Multipart upload.** An archive above 5 GiB is refused *by name* rather than split. A single node's Store is orders of magnitude below that, and multipart is a second protocol with its own abort-and-clean-up failure modes — carrying it for a case that does not arise costs more than the case does. Revisit if a real node ever hits the limit; the error names the number so it is unmissable.
- **A restore button in the dashboard.** A restore replaces everything on the node and happens on a stopped one. It belongs at a terminal.
- **Signed archives.** Archives are AEAD-authenticated and hashed, so tampering is detected on read. There is no separate signature, so an archive cannot be *attributed* to a node cryptographically — which matters only for a bucket several nodes write to, and none do.
- **A fallback certificate for an unknown SNI**, and **the edge minting its own certificates**. The handshake refusal is deliberate: presenting some other host's certificate produces a name-mismatch error that reads as "this site is impersonated" rather than "this site has no certificate yet". And on-demand issuance in the edge would be tempting — no projection, no cold start — but issuance is *writing*, which is the one thing the edge does not do, and it would put a CA private key in the process that terminates untrusted public traffic.
- **`kanea ca rotate`, and any route that returns the CA key.** Rotation means re-trusting every device; a command for it implies it is cheap. Deleting the Store key is the honest mechanism. The key moves in the encrypted archive or not at all.
- **UDP, PROXY protocol, and a `bind` address on a published port.** UDP needs a session table with its own expiry and has no accept-time hook for the IP check — a different program wearing the same block's name. PROXY protocol would restore the client's source address and is a second wire protocol most homelab services do not speak, where a misconfiguration prepends garbage to the stream and presents as protocol corruption rather than a config error. A `bind` address is genuinely useful and still costs a DHCP-renew failure mode and a whole second dimension of collision detection, which `ip_restriction` already covers in intent.
- **`tls = true` on a published port.** The certificate is selected by SNI, and a client connecting to `https://192.168.1.10:8443` sends none. It would work only for a client that has a name — and a client with a name has :443. A second HTTPS port is `kanea-edge --https :8443`.
- **A `retries_total` metric.** Traefik has one and the reverse proxy does not retry, so ours would be permanently zero — which reads as "retries are working" rather than "there are none". A metric that is always zero is worse than an absent one.
- **A router level in the metrics.** Traefik splits router from service; Kanea does not have the concept — a route *is* a service — so `kanea_edge_router_*` would duplicate `kanea_edge_service_*` exactly, at double the series.
- **A shipped Grafana dashboard.** The series follow Traefik's `_service_`/`_entrypoint_` naming precisely so an existing dashboard is a find-and-replace away, and a bundled JSON is a second thing to keep in step with every metric rename.

**Known limits** (true today, not decisions):

- **S3 interoperability is established against MinIO only.** CI runs the client against it and MinIO verifies SigV4, so the signature is one a real service accepts. AWS S3, R2, B2 and Wasabi have not been in the loop, and each has quirks around addressing style and region handling.
- **Releases publish no SBOM**, which §14 A06 and §21 both require. It is why §20 M10's exit criterion is `v0.1.0 tagged` rather than v1.0 (PRD v1.29): the gap is small — a `syft` step in `release.yml` writing SPDX JSON per archive, listed in `checksums.txt` so the existing cosign signature extends over it — but until it is closed, a v1.0 would fail its own non-functional requirements.

## Binding constraints (never violate these)

These come from PRD §18 and the security review. Violating them is a bug, even if the code works.

1. **PRD amendment discipline** — any deviation from the PRD requires editing `PRD.md` first (bump version, add an amendment note). No stealth architecture changes.
2. **State** — all mutations go through the `Store` interface with monotonic indexes (Raft-FSM-compatible shape). **Metrics and logs never touch the Store** (in-memory TS + file pipelines only). bbolt is single-writer: keep read transactions bounded/paginated.
3. **Process split** — `kanead` (control plane) and `kanea-edge` (ingress) are separate processes from one binary. Never couple edge traffic to control-plane lifecycle.
4. **Secrets** — referenced as `secret:<path>`, never inlined; **project-scoped at validation time** (a spec may not reference another project's secrets); injected via tmpfs files by default, env vars only as the documented weaker option; never logged; write-only over API/MCP.
5. **Naming** — project/service names are DNS-1123 labels, enforced at parse time. Names compose into DNS; `description` carries free text.
6. **Workload hardening defaults** — drop ALL capabilities, `no-new-privileges`, default seccomp, no `privileged` escape hatch in the v1 spec, per-alloc PID/IPC namespaces.
7. **Security gates are release gates** — `govulncheck`, `gosec`, `gitleaks`, `npm audit` must pass; OWASP Top 10 mapping (PRD §14) is reviewed per milestone. Auth is deny-by-default on every API/WS/MCP route.
8. **Backpressure discipline** — log drains are non-blocking with drop counters; a full pipeline must never block a workload's `write()`.
9. **Derived state** — datapath state (pinned BPF maps, programs, links) is always rebuildable from the Store; never persist or restore anything under the bpffs pin root.
10. **No Kubernetes dependencies.** No client-go, no CRDs, no kube imports, ever.
11. **Resource isolation** — the control plane (`kanead`, `kanea-edge`, containerd, buildkitd) has a kernel-guaranteed memory floor via cgroups v2 `memory.min` (default 1 GiB, PRD §5.2.11) and `OOMScoreAdjust=-900`; all workloads run under one parent cgroup with `memory.max` = total RAM − reserve. No container ever runs unlimited (defaults apply when `resources` is omitted, PRD §6.2 R11). Never use `mlock` on the Go control plane (`RLIMIT_MEMLOCK` + GC heap growth = crash risk) — the guarantee comes from cgroup protection + OOM-killer policy.

## Coding conventions

- **Go:** standard project layout; `goimports`-formatted; no global state (dependencies injected); errors wrapped with `fmt.Errorf("...: %w", err)`; context plumbed through all blocking calls; interfaces defined at the consumer, small and focused (`Store`, `Scheduler`, runtime/network drivers).
- **Logging:** everything logs through `log/slog` via `internal/logging`; components receive a `*slog.Logger` by injection. The stdlib `log` package is **depguard-banned**; direct `fmt.Print*` is **forbidigo-banned** (CLI output lives in `cmd/kanea` and goes through `fmt.Fprint*(os.Stdout/os.Stderr, …)`). Daemon file sinks rotate via lumberjack (bounded size/backups, gzip); workload logs follow PRD §17 (non-blocking drains, drop counters) and must never let a rotation stall a workload `write()`.
- **HCL:** all spec changes extend `internal/jobspec` schema with validation errors carrying file/line diagnostics; keep the PRD §6 examples valid.
- **Dashboard:** TypeScript strict; shadcn/ui components only (no new component lib); all user-controlled strings escaped (XSS — PRD §14 A03); live data via the single multiplexed WS.
- **Commits/PRs:** conventional commits (`feat:`, `fix:`, `chore:`, `docs:` …), one logical change per PR, `make check` green required. PR template enforces the binding constraints.
- **Tests:** table-driven; reconciler and jobspec validation must have >80% coverage — they are the correctness core.
