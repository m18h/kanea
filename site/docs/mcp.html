Guides

AI agents (MCP)

Connect an agent to a node over the Model Context Protocol, decide how much it may do, and look up the tools it gets. The server is the kanea binary itself, so there is nothing extra to install.

An agent has its credential's authority and nothing more

Every tool works by sending a request to the node's own API with the caller's credential. A tool cannot do anything that credential could not do at the REST API. No tool reads a secret, at any tier.

Use stdio when your editor runs on the node. Use HTTP from a laptop, which includes every Mac, because kanead runs on Linux only. Use HTTP also when the agent should be read-only: it is the transport where you choose a role.

Connect over stdio, on the node

kanea mcp talks to kanead over the unix socket and speaks MCP on stdin and stdout. --verbose logs protocol activity to stderr.

  1. Join the kanea group

    Your editor runs as you, and the socket is root-owned. Run sudo usermod -aG kanea $USER, then log out and back in. kanea ps now works without sudo.

    Membership is root-equivalent, like docker's group, so an agent on this transport is always an admin. For less, use HTTP with a viewer token.

  2. Register the server with your client

    Use the entry for your client below. Each one runs kanea mcp as a subprocess.

  3. Check the tool list

    Ask the client to list its tools. All 25 from the table below appear, because the socket carries the admin role.

Claude Code

claude mcp add kanea -- kanea mcp

Add --scope project to write the entry into the repository's .mcp.json, so everyone on the project gets it. The file form: 

{
  "mcpServers": {
    "kanea": {
      "command": "kanea",
      "args": ["mcp"]
    }
  }
}

opencode

In opencode.json at the project root, or in ~/.config/opencode/opencode.json: 

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "kanea": {
      "type": "local",
      "command": ["kanea", "mcp"],
      "enabled": true
    }
  }
}

Codex

codex mcp add kanea -- kanea mcp

The command writes this to ~/.codex/config.toml:

[mcp_servers.kanea]
command = "kanea"
args    = ["mcp"]
A client that connects and then does nothing

stdout is the protocol channel. A wrapper script that prints anything to it corrupts the stream. Keep wrappers silent, and read --verbose output from stderr.

Connect over HTTP, from anywhere

The same server answers at /mcp on the API listener. A socket-only node has no HTTP transport: set bind.api_addr first, as in Change the listen address.

  1. Create a token for the agent

    On the node, pick the role and an expiry:

    sudo kanea token create --role viewer --expires-in 720h agent-readonly   # can look, cannot change
sudo kanea token create --role admin  --expires-in 720h agent-deploy     # can deploy, scale and stop

    The secret is printed once, on stdout. Sign-in and access covers listing and revoking tokens.

  2. Make the agent's machine trust the node

    A node serves a self-signed or node-CA certificate unless its listener uses acme. Install the CA that kanea ca show prints on the machine running the agent. Without it the TLS handshake fails before MCP starts.

  3. Register the endpoint with your client

    Use the entry for your client below, with the token in an Authorization: Bearer header. A viewer token lists 13 tools and an admin token lists 25.

Claude Code

claude mcp add --transport http kanea https://192.168.1.10:8600/mcp \
  --header "Authorization: Bearer $KANEA_TOKEN"

opencode

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "kanea": {
      "type": "remote",
      "url": "https://192.168.1.10:8600/mcp",
      "enabled": true,
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

Codex

[mcp_servers.kanea]
url = "https://192.168.1.10:8600/mcp"
bearer_token_env_var = "KANEA_TOKEN"
A JSON entry with a url needs a type

Claude Code reads an entry with a url and no type as stdio and skips it with a message. opencode needs "type": "remote" for the same reason. This usually happens when an mcpServers block is copied from another client.

The endpoint is request and response only. Each POST carries one message and gets its reply, and the server opens no server-to-client stream.

The tools

The server registers 25 tools in three tiers: 13 read, 9 mutate and 3 destructive. The caller's role decides which tiers it sees. A viewer token gets the read tier only: the other tools are absent from tools/list, so the model cannot propose calling one.

get_servicereadShows one service's declared state. Secrets appear as references, never values.
list_allocsreadLists allocs with state, restarts and health.

get_eventsreadReads the event feed, newest first.
get_node_statsreadSummarises the node: version, what is declared, running and failing, CPU, memory and load.
get_service_statsreadCurrent CPU, memory, request rate and p95 latency for a service and its allocs.
list_pipelinesreadLists build and deploy runs with state, commit and duration.
list_storagereadLists the volumes services declare and which services mount them.
list_backupsreadLists backup archives and reports whether replication is working.
get_auditreadReads the audit log. The API allows this to admins only.

scale_servicemutateSets a service's replica count.
restart_servicemutateRolls a service's containers through its update policy.

TierToolsNeeds
Read13viewer or admin

Destructive3admin, and confirm: true on the call

get_audit is the one read tool a viewer cannot use. It is listed, and the call returns 403, because the API decides and the tiers only describe.

A destructive tool called without confirm: true returns a refusal as its result. The refusal tells the model to call again only if the operator explicitly asked, and that the action cannot be undone. The gate exists so a transcript shows the action was deliberate.

Every call is recorded in the audit log under the token's id, like any other API request. The dashboard's audit tab, GET /v1/audit and get_audit all show it.

Resources

The server also publishes read-only resources, for clients that attach context by URI. They return what the matching read tools return.

URIContent
kanea://projectsEvery project on the node.
kanea://eventsThe event feed, newest first.
kanea://node/statsThe node summary.
kanea://projects/{project}/servicesThe services a project declares.
kanea://services/{project}/{service}/statusOne service's declared state and its allocs.
kanea://services/{project}/{service}/logsThe tail of a service's logs.

Decide what to hand over

  • Start with a viewer token. It covers diagnosis: what is deployed, what is failing, the logs, the events and the stats. It cannot change anything.
  • Give admin only when the agent should deploy. apply_spec, scale_service and deploy_service are real deploys, with the same rolling-update rules and health gates as yours.
  • Prefer HTTP with a token over stdio. Socket access is root-equivalent, so stdio has no read-only form.
  • Set an expiry. kanea token create warns when a token never expires. --expires-in 720h limits how long a leaked editor config is useful.
  • Do not plan around secrets. No tool reads one. A spec references secret:<project>/<name> and the agent never sees the value.
