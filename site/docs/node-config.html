Node config (kanea.hcl)

/etc/kanea/kanea.hcl is the node config: every setting of kanead and the edge on this machine. This page lists every stanza and attribute, with its type and default.

The file belongs to whoever owns the machine. A spec can reference what the file permits and can never add to it, so somebody who can push to a synced repository cannot grant themselves a host path or a device.

The rules of the file

  • The path is fixed. Both daemons read /etc/kanea/kanea.hcl and nothing else. They take no flags and no arguments.
  • It is read once, at startup. Nothing watches or reloads it, so an edit needs a restart. See Apply a change.
  • An absent file means every default. Every attribute is optional, and one left out takes the default in its table below. kanea init writes the file with the values it settled; see Install a node.
  • A malformed file refuses startup. A file that does not parse, or breaks a stanza's rules, stops the daemon with an error naming the file and line. Nothing is half applied.
  • It is trust-checked before it is parsed. It must be a regular file, owned by root or the daemon's own uid, and not group- or world-writable. World-readable is fine: it holds policy, not secrets.
  • An unknown attribute inside a stanza is an error. There it is almost always a typo, and a misspelt allowed_host_paths would be a control that quietly did nothing.
  • An unknown top-level stanza is a startup warning that names it. The daemon starts and ignores the stanza.
  • The edge reads only bind and edge. A mistake in any other stanza stops kanead and never stops ingress. A syntax error anywhere in the file stops both.

Four conventions hold for every attribute:

  • A duration is a string such as "30s", "5m" or "12h".
  • A list is an HCL list, ["a", "b"], never a comma-separated string.
  • An address, path or URL that can be switched off takes the literal "off". Its table row says so.
  • A credential is a secret:<path> reference into the node's store, never the value itself. See Secrets.

network

kanead hands out every address itself, so treat these ranges as fixed once the node is installed. kanea init writes node_cidr and cluster_cidr into the file for that reason. There is no driver to choose: every node runs the eBPF datapath.

AttributeTypeDefaultMeaning
node_cidrstring"10.244.0.0/24"The subnet alloc addresses come from. Its .1 is the node's own address on that subnet.
cluster_cidrstring"10.244.0.0/16"The routed range, masqueraded on egress. It must contain node_cidr.
service_cidrstring"10.201.0.0/16"The pool service frontend addresses come from. It must not overlap the other two.
node_cidr6stringnoneThe IPv6 alloc subnet. A ULA range is recommended.
cluster_cidr6stringnoneThe routed IPv6 range. It must contain node_cidr6.
service_cidr6stringnoneThe IPv6 pool for service frontends.
bpf_dirstring/sys/fs/bpf/kaneaThe bpffs directory where the eBPF maps, programs and links are pinned.

The three IPv6 attributes come together or not at all. Setting all three makes the node dual-stack.

dns: the internal resolver

The internal resolver answers <service>.<project> names itself and forwards everything else to upstreams. Pin the list on a node whose resolv.conf DHCP rewrites.

AttributeTypeDefaultMeaning
listenstringthe .1 of network.node_cidr, port 53The internal resolver's listen address. "off" disables the resolver.
upstreamslist of stringsthe host's /etc/resolv.confThe resolvers external names are forwarded to. Each entry is an address or host:port; a bare address gets :53.

An empty upstreams list is refused, because it would turn every external name into a failure. To follow the host's resolvers, leave the attribute out. An alloc never sees this list: its resolv.conf names the internal resolver alone.

storage: volumes and the host-path allowlist

AttributeTypeDefaultMeaning
volume_dirstring<data_dir>/volumesThe root directory for local volumes.
allowed_host_pathslist of stringsempty (no host volumes)The parent directories a host volume may mount from.

A host volume mounts a directory that already exists on the node, and the node decides whether it may. A spec's path must sit inside one of allowed_host_paths, checked after symlinks are resolved. A path outside every entry fails the alloc.

kanead refuses to start when an entry is not absolute, does not exist, or is "/". An explicit empty list is legal and means no host volumes. The spec side is in Volumes and host access.

images: pull policy and cleanup

AttributeTypeDefaultMeaning
pull_policystring"if-not-present"Where images may come from for a service that does not say. The other value is "never".

Set "never" on a node that must not reach a registry: air-gapped, or with images preloaded from an offline bundle. A service's own task.pull_policy wins over this default. "always" is refused here, because it means automatic updates for every service on the node.

images.gc: image garbage collection

Every deploy and rollback leaves its previous image behind. The image garbage collection deletes them, and this nested block tunes or disables it.

AttributeTypeDefaultMeaning
enabledbooltrueRuns the image garbage collection.
intervalduration"12h"How often a sweep runs. The floor is 10m.
min_ageduration"48h"Images younger than this are never deleted. The floor is 1h.
keepnumber2The newest images kept per repository that something still uses, as rollback material.

An image is deleted only when all three hold:

  • Nothing references it: no service's image, pinned digest, rollback target or init step, and no running alloc.
  • It is older than min_age.
  • It is not among the newest keep of a repository something still uses.

A node whose pull_policy is "never" collects nothing, because a preloaded image cannot be pulled again. kanea images lists what the node holds and can run one sweep on demand; see the CLI reference.

device and socket: grants

A spec names a grant, never a path. The node holds the mapping from a grant's name to a device or socket, and lists the projects that may claim it. The spec side is in Volumes and host access.

AttributeOnTypeDefaultMeaning
the block labelbothstringrequiredThe grant name a spec references. It must be a DNS label, and unique within its kind.
nodesdevicelist of stringsrequiredAbsolute device node paths such as /dev/dri/renderD128. "Node" here means a device node, not the machine.
modedevicestring"rw"The cgroup permissions: a combination of r, w and m. m (mknod) applies only if you write it.
pathsocketstringrequiredOne absolute socket path, with no .., and not /.
allowbothlist of stringsrequiredThe projects that may claim the grant. An empty list is refused.

Paths are resolved and type-checked for each alloc, not when the file loads. A grant naming a device that is absent fails that alloc with a message naming the grant, and kanead keeps running. A spec asking for a grant the node does not hold is refused with a list of the grants it does hold.

A socket grant is root on this node

A container holding the runtime socket can start other containers without the hardening defaults, and nothing contains that. The control is that the grant is made on the machine, in a file no spec author can write, and names its projects.

variables: node-wide spec defaults

Each attribute in variables is a value every spec on this node can reference as ${name}. Use it for a node's domain or storage root, so specs do not repeat it.

  • A spec's own variables block wins over the node's, and a value passed on the command line wins over both.
  • Values are strings, numbers or bools. Lists and objects are refused.
  • A value is a literal: it cannot reference another variable.
  • Five names are reserved: GIT_SHA, GIT_SHA_SHORT, GIT_BRANCH, KANEA_PROJECT and service.
Never put a secret here

The API serves this stanza to any authenticated caller. Store secrets with kanea secret put and reference them as secret:; see Secrets.

Apply a change

  1. Edit the file

    sudo $EDITOR /etc/kanea/kanea.hcl

    Keep it owned by root and mode 0644. On a node that must not refuse a start, copy the file aside first.

  2. Check it loads

    sudo kanea doctor

    kanea doctor reads the node config. A file that does not load shows as a failed check with the error.

  3. Restart kanead

    sudo systemctl restart kanead

    After a change to bind.edge_http, bind.edge_https or the edge stanza, also run sudo systemctl restart kanea-edge.

  4. Confirm it came back

    systemctl is-active kanead kanea-edge
journalctl -u kanead -n 20

    Both units report active. The log names the file it loaded, and warns about any top-level stanza it did not recognise.

If kanead does not come back, the log holds the error with the file and line. Fix the file and restart again; see kanead will not start after editing kanea.hcl.

What needs no restart

The file is read once, but two kinds of file it points at are re-read when their content changes:

  • a renewed certificate or key file named by a certificate block;
  • a rotated credential file named by a provider block.

If a new version of such a file is unusable, kanead keeps the last good one. Changing the block itself needs a restart.

What a restart costs

  • Running workloads keep running. Restarting kanead does not stop containers.
  • Ingress keeps serving. The edge is a separate process and serves the last route table it read, whether or not kanead is up.
  • Change pauses for the second or two kanead takes to return: deploys, scaling, certificate renewal, the API and the dashboard.

Restarting kanea-edge does interrupt ingress briefly, so restart it only for the attributes it reads. The same split across every daemon is in Check services.

A complete file

Every stanza and attribute in one file. A value shown is the default unless its comment says otherwise, so a real file is usually a fraction of this.

/etc/kanea/kanea.hcl
# /etc/kanea/kanea.hcl - the node's one configuration file.
#
# Every attribute is optional. A value shown here is the default unless its
# comment says otherwise; an attribute left out means that default. kanead
# and kanea-edge read the file once, at startup: edit it, then restart them.

data_dir      = "/var/lib/kanea"         # state, the master key, volumes
alloc_log_dir = "/var/log/kanea/allocs"  # per-alloc workload logs
log_level     = "info"                   # debug | info | warn | error
base_domain   = "apps.example.com"       # no default; gives <service>.<project>.apps.example.com

# Node-wide spec variables: defaults every spec on this node may reference as
# ${name}. A spec's own variables block wins. Primitives only, never secrets:
# the stanza is served to any authenticated caller.
variables {
  domain = "home.lan"
}

# Every listener the node opens.
bind {
  api_socket = "/run/kanea/kanead.sock"  # the CLI's unix socket
  api_addr   = "192.168.1.10:8600"       # no default; omit for socket-only

  # How the API/dashboard listener is secured:
  #   acme        a public certificate; requires api_domain
  #   self-signed the node CA; names api_domain, else api_addr's host
  #   provided    the api_cert/api_key pair, loaded once
  #   plaintext   explicit HTTP; beyond loopback it is logged loudly
  # Unset: a pair means provided, loopback means plaintext, anything else
  # is refused.
  api_tls    = "acme"
  api_domain = "kanea.example.com"
  # api_cert = "/etc/kanea/tls/api.crt"  # provided mode's pair
  # api_key  = "/etc/kanea/tls/api.key"

  edge_http  = ":80"                     # the edge's public HTTP listener
  edge_https = ":443"                    # "off" serves plaintext only
}

auth {
  insecure_cookies = false               # true only behind plain HTTP

  # Single sign-on. No default: without an issuer, password login only.
  oidc {
    issuer        = "https://auth.example.com/realms/kanea"
    client_id     = "kanea"
    client_secret = "secret:shared/oidc"  # omit for a public PKCE client
    redirect_url  = "https://kanea.example.com/v1/auth/oidc/callback"
    scopes        = ["profile", "email"]  # beyond openid; [] requests none
    role_claim    = "groups"
    admin_claims  = ["kanea-admins"]
    viewer_claims = ["kanea-viewers"]
  }

  # Directory login. No default: without a url, no LDAP.
  ldap {
    url            = "ldaps://ldap.example.com"
    bind_dn        = "cn=kanea,ou=services,dc=example,dc=com"
    bind_password  = "secret:shared/ldap-bind"
    user_base_dn   = "ou=people,dc=example,dc=com"
    user_filter    = "(uid=%s)"
    group_base_dn  = "ou=groups,dc=example,dc=com"
    group_filter   = "(member=%s)"
    admin_groups   = ["cn=kanea-admins,ou=groups,dc=example,dc=com"]
    viewer_groups  = ["cn=kanea-viewers,ou=groups,dc=example,dc=com"]
    ca_file        = "/etc/kanea/tls/ldap-ca.pem"
  }
}

audit {
  retention = "2160h"                    # 90 days; "0" keeps entries forever
}

dashboard {
  enabled = true
  origins = []                           # extra Origins allowed to open the live websocket
}

# kanead is the IPAM: these are fixed when the node is installed. node_cidr
# must sit inside cluster_cidr, and neither may overlap service_cidr.
network {
  node_cidr    = "10.244.0.0/24"         # alloc addresses
  cluster_cidr = "10.244.0.0/16"         # routed range, masqueraded on egress
  service_cidr = "10.201.0.0/16"         # service frontends
  # The IPv6 trio comes together or not at all. No defaults.
  node_cidr6    = "fd00:10:244::/64"
  cluster_cidr6 = "fd00:10:244::/56"
  service_cidr6 = "fd00:10:201::/112"
  bpf_dir       = "/sys/fs/bpf/kanea"    # pinned maps, programs and links
}

dns {
  listen    = "10.244.0.1:53"            # default: the node CIDR's .1; "off" disables
  upstreams = ["1.1.1.1", "9.9.9.9:53"]  # default: the host's resolv.conf
}

storage {
  volume_dir = "/var/lib/kanea/volumes"  # default: <data_dir>/volumes
  # Empty by default: no spec can mount a host directory until a permitted
  # parent is named here.
  allowed_host_paths = ["/srv/kanea"]

One source, no precedence

The file is the only source of node configuration, so no setting can be overridden from elsewhere. A node installed with settings on its systemd units is converted automatically on upgrade; see Migrating from flags.
