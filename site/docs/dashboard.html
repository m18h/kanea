Guides

The dashboard

Open the dashboard from your own machine, choose how its listener gets a certificate, and find what each page does.

Reach the dashboard

kanead serves the dashboard on its API listener, the address the REST API and the MCP endpoint also use. Run this on the node to print the URL: 

kanea ui          # prints the dashboard URL
kanea ui --open   # and opens it in a browser

The URL carries the listener's port, 8600 by default: https://<node>:8600. Port 443 belongs to the edge, which has no route to the dashboard. The dashboard is not a service and takes no expose block.

What kanea init set up

kanea init asks where the API and dashboard listen, then writes the answer into the bind stanza of the node config. It ends by printing the dashboard URL and the admin account it created.

Your answerWhat you get
Enter, for 127.0.0.1:8600Plain HTTP on loopback. Only a browser on the node itself reaches it.
An address on your network, such as 192.168.1.10:8600HTTPS with a 10-year self-signed pair at /etc/kanea/api.crt and /etc/kanea/api.key. Init creates the pair once and leaves it alone on later runs.
The same, with --listen-cert and --listen-keyHTTPS with your own pair.
noneNo network listener. The CLI works over the unix socket and there is no dashboard.

Init refuses 0.0.0.0:8600, because the certificate it creates needs a host to name. Give a specific address, or write the stanza yourself with api_domain as below.

Change the listen address

  1. Edit the bind stanza

    Open /etc/kanea/kanea.hcl and set the address. This example serves the dashboard on one LAN address with a certificate from the node's own CA: 

    # /etc/kanea/kanea.hcl
bind {
  api_addr = "192.168.1.10:8600"
  api_tls  = "self-signed"
}

    Remove api_cert and api_key if init wrote them: a managed mode beside a pair is refused at startup.

  2. Restart kanead

    Run sudo systemctl restart kanead. Running workloads and the edge are not interrupted. The dashboard and API return within a few seconds.

  3. Open the new URL

    kanea ui prints https://192.168.1.10:8600. If kanead did not come back, see kanead will not start after editing kanea.hcl.

Every bind attribute, its default and the combinations kanead refuses are in Node config: bind.

Choose the certificate

bind.api_tls takes one of four modes. Pick by who has to trust the dashboard:

ModeUse it whenWhat you do
self-signed The node is on a home or office network with no public name. Install the node's CA on each device once: kanea ca show prints it. kanead issues and renews the certificate, with an IP SAN when api_addr is a bare address.
acme The node has a public name and browsers should trust it without setup. Set api_domain and acme.email, point a DNS record at the node, and keep port 80 reachable with the edge running.
provided Something else manages the certificate. Set api_cert and api_key to the PEM pair. Restart kanead after replacing the files.
plaintext A trusted network where you accept HTTP. Nothing. kanead logs a warning at startup and the session cookie loses its Secure attribute, so sign-in works over HTTP.

With api_tls unset, a pair means provided and a loopback address means plaintext. Any other address gets no listener: kanead keeps running on its socket and logs the reason.

An acme certificate uses the same account and renewal loop as your services. Domains and HTTPS explains issuance.

Keep the port in the URL

https://kanea.apps.example.com without :8600 reaches the edge on port 443. The browser then reports a TLS error, which looks like a broken certificate. Troubleshooting covers this and the short wait before a new certificate arrives.

Sign in

Sign in with the admin account kanea init created. Sign-in and access covers more accounts, single sign-on and directory login.

An account is an admin or a viewer. A viewer reads every page except Settings and Updates and cannot change anything. The sidebar shows who you are and which role you hold.

To turn the dashboard off and keep the API, set dashboard.enabled = false. See Node config: dashboard.

Tour of the pages

The sidebar lists nine pages. Actions on them write desired state and let kanead converge, exactly as the CLI does.

Dashboard

The landing page answers "should I worry". It shows anything that needs attention first, then counts, the node's CPU, memory and load, your services beside recent events, and one line on backup health.

When the node has a visible GPU, its card charts utilisation first and VRAM second. A card whose driver reports neither is named beside a dash.

Projects

Each project is listed with its services, how many allocs are running, where its spec comes from and when it last synced.

  • Sync re-reads a git-backed project now, the same read the poll loop does.
  • Stop scales every service in the project to zero.
  • Remove deletes the project's services and pipeline configuration, after a dialog that names what will go.

There is no "new project" button. A project exists once a service declares itself into that name.

Services

The list shows what is declared and how much of it is running, with CPU, memory, request rate and p95 per service. Search, filter by status, or sort. Deploy service opens the spec editor.

A service page

Four charts sit at the top: CPU, memory, requests per second and p95 latency. Below them are tabs:

TabShows
AllocationsEach alloc with its state, health and restarts, a button for its logs and, for an admin, a shell into it.
LogsThe live stream, with a filter, copy, download and a full-screen view.
SpecThe declared image, replicas, resources, domains, published ports and dependencies.
EventsEvents for this service only.
EdgeRequest and byte totals from the edge. Present when the service has ingress traffic to report.

The actions, for an admin:

  • Restart rolls the service through its update policy. On a service that is down it reads Start.
  • Open follows the service's public address in a new tab, with a menu when it has several.
  • Scale sets the replica count.
  • Edit spec opens the spec editor with the current spec.
  • Stop scales to zero and Remove deletes the declaration. Both ask for a second click. Volume data is kept.

Where a service declares a scaling block, the Scale picker stops at that policy's bounds and says so: 

Currently 3 · allowed 2-10
Autoscales between 2 and 10: a manual count outside that is refused,
and one inside it stands until the next autoscale decision.

Open uses https unless the route declares tls { mode = "plaintext" }. A route with no domains is left out, because its generated name under base_domain is visible to admins only.

A restart or deploy shows as rollout progress. Memory reads 108 MiB / 256 MiB, or 512 MiB / all memory when the spec declares no limit.

The spec editor

Deploy service and Edit spec open the same editor. kanead validates the spec and renders the preview with this node's base domain, so the preview is what an apply does here.

On a project synced from git, the editor warns that the next sync overwrites what you apply here. Tick the box to confirm you read it.

Pipelines

Build and deploy runs, newest first, with state, commit and duration. A run's page follows the build log while it runs, offers the log as a download, and shows the digest that was built.

Functions

WebAssembly functions, with their status and invocations per minute. A function is a service underneath, so its detail, restart and scale live on its service page. Deploy function opens the spec editor.

Storage

Every storage resource that a volume mounts, with driver, target, host path and measured usage against the size the volume declared.

A size is a budget and nothing enforces it. Usage that has not been measured shows a dash, which for an s3 volume is permanent. Volumes and host access has the drivers.

Events

The feed of what happened on the node: deploys, crashes, health changes, scaling decisions, certificates and builds. They are the same events your notification channels receive. Filter by severity or search.

The audit filter switches to the audit log: who did what, when and from where. It is admin-only.

Backups

The page leads with replication health: when a backup last succeeded. Below it is the archive list.

  • Snapshot now takes a backup on demand.
  • Verify decrypts and reads one archive in full, then reports the verdict.
  • Stage records a restore request that kanead applies at its next start.

Back up a node explains restoring.

Settings

Settings is admin-only and has five tabs:

TabWhat you do there
NodeRead what the node config decided: listen address, TLS, base domain, DNS, directories and the published-port policy, plus the network mode the system gave it. Read-only: edit /etc/kanea/kanea.hcl and restart kanead to change them.
BackupSet the backup destination, a directory or S3. kanead probes a new destination with a test write before saving it. See Back up a node.
NotificationsConfigure channels node-wide and per project. Each has a test button.
AccountsManage accounts and API tokens. See Sign-in and access.
AuditRead the audit log.

Updates

When a newer Kanea release exists or the node needs a reboot, the sidebar shows an "updates available" link for an admin. It opens the Updates page, at /updates.

The Kanea half checks for a release and runs the upgrade, the same sequence as sudo kanea upgrade. The node asks GitHub only while an admin has the dashboard open, and caches the answer for an hour.

The OS half reports pending packages with a security count, when the package lists were last refreshed, a pending reboot, and the host components against their pinned versions. Kanea installs no OS package: the page names the apt command to run on the node.

Lists, charts and display

  • Every list keeps its search, filter and sort in the URL. The Back button restores them, and /services?q=api&status=degraded is a link you can send.
  • Tables page at 20, 50 or 100 rows.
  • The browser tab names the page, down to the service: shop/web · Kanea.
  • A chart arrives with its recent history already drawn. An empty one reads no samples yet, which is normal for about ten seconds after kanead restarts.
  • The icon beside the version switches light and dark. The cog beside your name sets the date order: yyyy-MM-dd, dd/MM/yyyy or MM/dd/yyyy. Both are stored in your browser only.
